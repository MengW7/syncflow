# 第 2 周任务清单

来源：`docs/tasks/week-02.pdf` 的「任务」一节。状态按当前仓库核对。

## 1. 编写数据库迁移或初始化脚本

- [x] 已完成，已提交

`scripts/init_db.sql`、`scripts/migrate.ps1`、`scripts/migrate.sh`。脚本可重复执行。开发库与 `syncflow_test` 分开初始化。

## 2. 创建 sync_jobs、sync_records、sync_errors 表

- [x] 已完成，已提交

三张表、字段、主键、`UNIQUE(job_id, external_id)`，以及 `(status, created_at)`、`(created_at)`、`(job_id)`、`(job_id, row_number)` 索引都在初始化脚本里。

## 3. 实现 MySQL 连接、配置和健康检查

- [x] 已完成，尚未提交

`backend/app/core/config.py` 读取 MySQL 配置并拼出连接串，含 `MYSQL_TEST_DATABASE`。`backend/app/db/session.py` 提供业务连接池，可单独连测试库。`/healthz` 只表示进程存活。`/readyz` 用短连接执行 `SELECT 1`，并同时检查 Redis；失败返回 503 `NOT_READY`，细节只有 `ok` 或 `unavailable`。

## 4. 实现创建任务接口

- [x] 已完成，尚未提交

`POST /api/v1/jobs` 已挂到应用。`multipart/form-data` 接收必填 `file` 和可选 `name`。只接受 `.csv`，超限返回 400 `FILE_TOO_LARGE`。文件以 `{job_id}.csv` 写入受控目录，并保存 SHA-256。成功立即返回 201，体里只有 `id`、`name`、`status`、`created_at`。入队失败时任务记为 `FAILED`，并写入 `last_error_code`。

## 5. 实现任务详情接口

- [x] 已完成，尚未提交

`GET /api/v1/jobs/{job_id}` 已挂到应用。返回 `id`、`name`、`status`、`source_file_name`、`total_records`、`success_records`、`failed_records`、`retry_count`、`last_error_code`、`last_error_message`、`created_at`、`started_at`、`finished_at`。不存在返回 404 `JOB_NOT_FOUND`。响应不包含 `stored_file_path`、数据库连接信息或堆栈。

## 6. 实现任务列表接口

- [x] 已完成，尚未提交

`GET /api/v1/jobs` 已挂到应用。`page` 默认 1、最小 1；`page_size` 默认 20、最大 100。可按 `status` 筛选，非法状态、页码或每页条数返回 400 `INVALID_REQUEST`。排序为 `created_at DESC, id DESC`。`data` 是列表，`meta` 含 `page`、`page_size`、`total`。

## 7. 实现最小 Worker

- [x] 已完成，尚未提交

`python -m app.worker` 从 Redis 取出任务 id，把 `PENDING` 改为 `RUNNING` 并写入 `started_at`，随后直接改为 `SUCCESS` 并写入 `finished_at`。日志包含时间、级别、`service=worker` 和 `job_id`。Docker Compose 里 `worker` 与 `api` 分开运行。

## 8. 增加请求参数校验

- [x] 已完成，尚未提交

分页参数、状态白名单（`PENDING`、`RUNNING`、`SUCCESS`、`FAILED`）、文件扩展名、文件大小和任务名称长度都在现有接口上校验。名称超过 128 个字符返回 400 `INVALID_REQUEST`。未预期的数据库异常只返回 `INTERNAL_ERROR`，响应里没有堆栈或连接信息。

## 9. 设计统一错误响应

- [x] 已完成，尚未提交

成功响应为 `{ "data": {}, "meta": {} }`。失败响应为 `{ "error": { "code", "message", "details" } }`。本周错误码：`INVALID_REQUEST`、`INVALID_FILE_EXTENSION`、`FILE_TOO_LARGE`、`JOB_NOT_FOUND`、`INTERNAL_ERROR`。创建、详情和列表接口都走这套格式。

## 10. 实现 React 任务列表页和基础任务详情页

- [x] 已完成，尚未提交

列表页 `/` 调用 `GET /api/v1/jobs`。状态筛选和页码写在 URL 里，翻页保留筛选。展示名称、状态、文件名、总数、成功数、失败数、创建时间和详情入口。状态同时有中文和颜色。没有任务时显示空状态和创建入口；请求失败时显示重试。

详情页 `/jobs/:jobId` 展示状态、源文件名、统计、创建/开始/结束时间和最近错误。任务不存在时提示并返回列表。时间用浏览器本地时区，格式 `2026-01-01 18:00:00`。

API 类型在 `frontend/src/api/types.ts`。未匹配路由显示 404。`npm run build` 已通过。

## 11. 为正常和异常场景编写测试

- [x] 已完成，尚未提交

`backend/tests/test_jobs_api.py` 覆盖创建成功、参数异常、数据库异常和分页边界。集成测试连接 `syncflow_test`，上传目录和 Redis 队列都用测试专用值，不写开发库 `syncflow`。FastAPI 在 `/openapi.json` 提供 OpenAPI，测试会检查创建、列表和详情这三条路径。
