# V1.0 三分钟演示

演示前按 `README.md` 第 6 节把 MySQL、Redis、API、Worker 和前端都启动。浏览器打开 http://127.0.0.1:5173 。准备 `samples/ok.csv`、`samples/row-errors.csv` 和 `samples/bad-header.csv`。`.env` 里的 `MAX_RECORDS_PER_JOB` 保持 `10000`。

## 0:00–0:40 创建并立刻返回

打开「创建任务」。选择 `samples/ok.csv`，确认页面显示文件名和大小。提交。按钮在请求期间不可点。成功后进入详情。

说明这一下只创建任务：接口返回时状态还是「等待中」或很快变成「处理中」，页面每 3 秒自己刷新。不要等上传请求把整份 CSV 算完。

## 0:40–1:20 成功统计

等详情变成「已完成」。指出总数 2、成功 2、失败 0，结束时间已经有了，没有「查看错误明细」。这与 `samples/README.md` 里 `ok.csv` 的期望一致，也与 `sync_records` 的两行一致。

## 1:20–2:10 行级错误和文件级错误

回到创建页，上传 `samples/row-errors.csv`。终态是「部分成功」，总数 8、成功 1、失败 7。打开「查看错误明细」，能看到行号 3 到 9，以及 `FIELD_REQUIRED`、`EXTERNAL_ID_INVALID`、`EXTERNAL_ID_DUPLICATE`、`NAME_TOO_LONG`、`AMOUNT_INVALID`、`DATE_INVALID`、`ROW_COLUMN_COUNT_MISMATCH`。

再上传 `samples/bad-header.csv`。终态是「失败」，三个计数都是 0，仍然有「查看错误明细」。明细里行号是 `-`，错误码是 `CSV_HEADER_INVALID`。说明文件级失败不能只靠失败数大于 0 来找入口。

## 2:10–3:00 现场改一处规则

打开 `.env` 的 `MAX_RECORDS_PER_JOB`，改成 `1`，保存后重启 Worker。再上传 `samples/ok.csv`。这次应变成「失败」，错误码 `FILE_TOO_MANY_ROWS`，计数仍是 0 / 0 / 0。

说明规则集中在这一个配置：解析器、导入和 Worker 都读它，不用改每一处校验。演示完把值改回 `10000` 并再次重启 Worker，否则后端测试会失败。

若时间剩一点，打开 http://127.0.0.1:8000/docs ，指出错误明细路径 `GET /api/v1/jobs/{job_id}/errors` 和状态里的 `PARTIAL_SUCCESS`。
