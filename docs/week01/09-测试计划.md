## 测试计划

### 1. 异常场景
| 编号 | 场景 | 期望 |
| :--- | :--- | :--- |
| E1 | 未传文件 / 非 csv 类型文件 | 不创建任务 |
| E2 | 文件 > 10MB | 413 FILE_TOO_LARGE |
| E3 | 表头错误 | failed，INVALID_CSV_HEADER |
| E4 | 空文件 | 任务 failed，EMPTY_FILE |
| E5 | 同一任务重复 sku | 记录第一个，后面出现的记录到错误表中 |
| E6 | 查询job_id 不存在 | 404 JOB_NOT_FOUND |
| E7 | 创建后 Redis 短暂不可用 | 不丢任务或任务可被发现为失败 |

### 2. 测试范围
| 模块 | 内容 |
| :--- | :--- |
| **API** | `GET /healthz`、`GET /readyz`、`POST /api/v1/jobs`、`GET /api/v1/jobs`、`GET /api/v1/jobs/{id}`、`GET .../errors`、`GET .../records` |
| **上传** | multipart CSV、10MB 限制、落盘 `uploads/`、SHA-256、建 `jobs(pending)`、`LPUSH syncflow:jobs` |
| **Worker** | `BRPOP`、状态流转、行校验、写 `job_records` / `job_errors` / `job_attempts`、部分成功 |
| **数据** | MySQL 四表、SKU 任务内唯一、`DECIMAL(12,2)`、UTC `datetime(3)` |
| **列表** | `page` 默认 1、`page_size` 默认 20 上限 100、`status` 过滤、`created_at DESC` |
| **Web** | `/` 列表、`/jobs/new` 上传、`/jobs/:id` 详情轮询、`/jobs/:id/errors` |
| **部署** | Compose: Web / API / Worker / MySQL / Redis |

### 3. 测试用例

1. **正向与完整流程**
* **01 基础端到端导入**
  * **步骤**：`POST /api/v1/jobs` 上传 `valid_10.csv`
  * **期望**：API 返回 `201`，状态为 `pending`，返回 `job_id` (UUID)；Worker 消费后终态为 `succeeded`，`total_rows=10`，`success_count=10`，`failure_count=0`，`records` 写入 10 条，`errors` 为空。
* **02 仅表头 0 数据行**
  * **期望**：`201` 建任务成功，终态为 `succeeded`，`total_rows=0`，所有计数值为 0（与 0 字节空文件区分）。
* **03 任务列表分页与状态过滤**
  * **步骤**：使用 `page`、`page_size` 及 `status` 参数查询 `/api/v1/jobs`。
  * **期望**：遵循统一信封 `{"data":{"items":[]},"meta":{"page","page_size","total"}}`，支持按状态过滤，默认 `created_at DESC` 排序。
* **04 任务详情与记录分页查询**
  * **步骤**：请求 `GET /api/v1/jobs/{id}` 与 `GET .../records?page=1&page_size=5`。
  * **期望**：详情字段完整（文件名、统计数、时间戳）；成功记录分页返回，金额保留两位小数。
* **05 UTF-8 BOM 兼容与跨任务重名**
  * **期望**：首行带 BOM 表头仍能正确解析 `sku`；不同任务允许出现相同 SKU（唯一索引作用域为 `(job_id, sku)`）。
* **06 1,000 行并发基线**
  * **期望**：上传 1,000 行合法 CSV，并发 Worker=2 运行时服务不崩溃且无重复入库。

2. **异常与输入校验**
* **01 上传前置校验拦截**
  * 缺少 `file`：返回 `400 VALIDATION_ERROR`。
  * 非 CSV 类型（如 .txt / .png）：返回 `415 UNSUPPORTED_MEDIA_TYPE`。
  * 文件超过 10MB：返回 `413 FILE_TOO_LARGE`，且无残留文件。
* **02 文件级结构错误**
  * 0 字节文件：Worker 标记 `failed`，错误码 `EMPTY_FILE`。
  * 表头缺失/列名不符：Worker 标记 `failed`，错误码 `INVALID_CSV_HEADER`。
* **03 行级混合错误**
  * **输入**：包含缺失字段、数值非法、字段超长、同一任务内重复 SKU 等。
  * **期望**：合法行写入 `records`，非法行写入 `errors`（包含 `raw_preview` 与行错误码）；既有成功又有失败时终态为 `partial_succeeded`，全错时为 `failed`。
* **04 资源与路由容错**
  * 查询不存在的 UUID 返回 `404 JOB_NOT_FOUND`。
  * 目录穿越防护：上传文件名含 `../../` 时规范化落盘，禁止逃逸出 `uploads/`。
* **05 依赖故障保护**
  * Redis 宕机或入队失败：`POST` 接口事务回滚返回 500，严禁残留无人消费的 pending 任务。
  * 组件宕机时 `/readyz` 探针返回 `503`。
* **06 统一错误响应信封**
  * 所有 4xx/5xx 错误严格包裹为 `{"error":{"code","message","details"}}`，不暴露系统堆栈与路径。
